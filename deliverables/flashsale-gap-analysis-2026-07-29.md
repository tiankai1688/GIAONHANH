# Flash Sale 路演方案 vs GIAONHANH 当前软件 —— 差距与优势对照

**日期**：2026-07-29
**场景**：融资路演方案 × 实际产品状态 差距分析
**对照对象**：路演方案「Flash Sale 越南全域小时达闪购平台」 vs 当前实现「GIAONHANH 越南小时达」原型/后端

---

## 一、核心结论

路演方案定位清晰、差异化强（跨店合并、0 佣金、骑手 100% 收益），而当前 GIAONHANH 软件已在**商业模式底层（0 佣金 + 配送补贴）**和**多端高保真原型**上高度对齐，这是最大优势。

但方案里最值钱的"杀手锏"——**跨多店合并一单、一次配送、只收一次配送费**——在当前原型里还没有真正落地（数据模型仍是"单商户订单"），这是必须优先补齐的第一差距。

---

## 二、优势（当前软件已具备 / 高度对齐）

### 1. 0 平台佣金 + 配送补贴模式 ✅
路演核心卖点"初创期 0 佣金、长期 3-5%、平台不抽骑手"——GIAONHANH 商业模式已定为"平台抽成恒为 0、配送费由平台补贴给骑手"，分账核心 `PaymentSplitService.php` 已落地。这是和 Grab/Shopee 22-28% 佣金最直接的差异化，**已经做出来了**。

### 2. 多端原生 App 高保真原型 ✅
C 端已建 8 屏（首页/商品/购物车/分类/结算/订单/追踪/我的），商家端已建 4 屏（概览/接单/订单详情/商品管理），骑手端、登录权限在设计。证明"美团式多品类一站式"不是 PPT 概念，已有可演示产品。

### 3. 越南本地化与支付合规 ✅
VI+ZH 双语、₫ 越南盾、河内场景；支付已做 MoMo v2 / ZaloPay（HMAC 验签）+ 聚合模式（Sepay/Payoo，规避二清）。路演"支付对接"要求已覆盖且更合规。

### 4. 后端骨架已搭 ✅
Laravel 11：商家入驻审核 / 商品 / 订单 / 支付分账 / 骑手调度 五条主线已有代码结构。路演三阶段"完善支付、地图、骑手调度系统"有地基。

### 5. 错位竞争定位已体现 ✅
品类覆盖餐饮 + 杂货 + 生鲜（C 端分类磁贴、商家端混合经营），符合"不与巨头抢午晚餐红海、主打家庭全天高频日用"的策略。

---

## 三、不足 / 差距（路演领先于当前软件）

### 🔴 P0 致命差距
1. **跨店合并下单（杀手锏未落地）**
   路演最大独家卖点。当前原型数据模型是**单商户维度**：购物车按"商户购物车卡"分商户、订单用 `order_no` 按单商户路由、结算按商户。没有"多商户加购 → 合并为一单 → 一次骑手取送 → 一次配送费"的逻辑。投资人一定会深挖，必须尽快做出可演示的合并下单流程。

2. **一单一次配送费的分账模型**
   `PaymentSplitService` 需扩展：多商户货款拆分 + 平台承担/收取单次配送费 + 骑手统一结算。当前分账按单笔订单，未覆盖跨店合并场景。

### 🟠 P1 重要差距
3. **骑手补贴规则引擎**
   路演强调"跨店单补贴、夜间补贴、雨天补贴、骑手 100% 收益"。当前骑手端仅有 UI 占位，补贴计算规则、动态定价未实现。

4. **T+1 结算与商家结算后台**
   路演"T+1 结算、无隐藏扣款、极简后台"是吸引小微商户的关键。当前后端未见结算模块 / 对账 / 提现流程。

5. **地图 API 真实集成**
   路演"地图、骑手调度系统"。当前骑手端地图为灰色占位，无真实路径规划 / ETA / 热力调度。

6. **前置仓自营 + 自营商超生鲜**
   路演第二阶段"搭建前置仓自营体系""自营商超生鲜进销差价"。当前纯平台模式，无自营库存 / 仓配。

### 🟡 P2 一般差距
7. **城市区域代理 / 合伙人系统**
   路演第二阶段"开放城市合伙人 / 区域代理""加盟费收入"。当前无代理分润 / 加盟管理模块。

8. **首页展位 / 活动专场增值服务（广告变现）**
   路演收入来源第 2 条。当前首页为固定 Banner，无商业化展位 / 竞价 / 专场后台。

9. **动态配送费定价模型**
   路演"用户端配送服务费（核心收入）"。当前配送费逻辑简单，缺距离 / 时段 / 峰值动态定价。

---

## 四、给投资人的诚实叙事建议

- 把"0 佣金 + 骑手 100% 收益"作为**已验证**优势（代码已有）。
- 把"跨店合并"作为**路线图核心里程碑**，明确 demo 时间表，不要过度承诺已上线。
- 把"地图 / 前置仓 / 代理"明确标注为第二阶段规划，避免被质疑交付能力。
