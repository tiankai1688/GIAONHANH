# 红队对抗审查 · GIAONHANH（2026-08-01，修订版）

> 三视角：**想搞垮产品的黑客** / **最挑剔的用户** / **最抠门的老板**。
> 每条弱点基于当前代码（`backend/` 实读），含 `file:line`、可利用路径、影响、严重度。
> **前提变更（本次修订核心）**：软件在中国开发、在越南上线、与中国无业务关系。
> → **PIPL（中国个保法）不适用**（无中国数据主体、无中国境内处理目的）。
> → 管辖法变为 **越南 PDPD（13/2023/NĐ-CP，及 2025 年新《个人数据保护法》趋势）** + 越南《消费者保护法》（2023）。
> → **新增跨境维度**：中国开发团队 + 越南数据这一结构，使"开发侧访问生产库/日志"构成 PDPD 下的**跨境处理**；任何崩溃上报/遥测若回连中国侧基础设施即构成**非法跨境传输**。该维度在三个视角下分别放大风险。
> 前几轮"立即修"已封堵项（明文落库、定位自动采集、登录无锁定、无注销、验签 fail-closed）不重复计入。

## 🕱 视角一：想搞垮产品的黑客（安全 / 可利用漏洞）

### 1. 🔴【致命】无地理围栏的 `nearby` 接口 = 全国客户 PII 拖库（叠加跨境违规）
- **位置**：`app/Http/Controllers/Api/RiderController.php:19-42` + `app/Http/Resources/OrderResource.php:41-45`
- **事实**：`nearby()` 筛选只过滤 `status` + `rider_id`，**完全无距离 WHERE**；客户端 lat/lng 仅用于显示 `distance_km`。所有 `picked` 未指派订单全国返回，`OrderResource` 直接序列化 `address/lat/lng/contact_name/contact_phone`。
- **利用**：任一登录骑手循环翻 query 即可拖走全平台**越南公民**的家庭住址 + 电话 + GPS + 购买内容。
- **影响（本前提下的升级）**：
  - 违反 **PDPD** 关于个人数据泄露的通报与保护义务，可被越方处以行政罚并责令暂停服务；
  - **跨境放大器**：若这批数据与在中国侧的开发/监控/分析系统有任何通路（见本视角 #6 维度），即同时构成 PDPD 下的**未经同意的跨境传输**（需数据主体同意 + 跨境影响评估 + 向公安部 A05 报备，否则违法）。

### 2. 🔴【致命】注册无 OTP 校验 → 无限伪造账号 farm 平台补贴券
- **位置**：`app/Http/Controllers/Api/AuthController.php:71-95`（注释 "OTP simulated"，直接 `issueTokens`）
- **事实**：`register` 仅校验手机号 9–11 位数字 + 密码长度，无真实短信验证，注册即发 token。
- **利用**：脚本批量注册百万级假 customer（随机越南手机号），每个领平台出资「新人券」，下单后取消/自刷，掏空补贴池。
- **影响**：直接现金燃烧，单位经济归零；假账号与真越南用户无法区分（无手机实名/KYC）。

### 3. 🟠【高】登录错误差异化 + 404/401 拆分 = 手机号枚举
- **位置**：`app/Http/Controllers/Api/AuthController.php:125-132`
- **事实**：未注册返回 `404`，密码错返回 `401`，文案不同；虽有 5 次/15 分钟按手机号锁 + `throttle:auth` 10/分，但无图形验证码、锁按手机号可换号绕过。
- **利用**：手机号字典批量试探，靠 404/401 区分"已注册/未注册"，锁定真实越南用户群后针对性撞库/钓鱼（钓鱼页可纯越南语，本地化成本归零）。

### 4. 🟠【高】公开、无节流、无设备绑定的 refresh 端点
- **位置**：`app/Http/Controllers/Api/AuthController.php:162-188`（`POST /api/auth/refresh`，public）
- **事实**：无 `throttle`、无 IP/设备指纹绑定。Refresh token 64 位随机 + sha256 存储（不可暴力），但一旦泄露（日志/反代/共享设备/上面 #1 拖库后社工），可任意位置 `refresh` 轮换，受害者被单会话设计静默踢下线——有信号无阻断、无冻结。

### 5. 🟠→🔴【高】支付成功但 IPN 丢失 = 资金已扣、订单永不履约 + 无对账任务
- **位置**：`app/Http/Controllers/Api/PaymentController.php:96-122`（钱包路径依赖 IPN 翻 `paid`）；全仓**无队列 worker、无 reconciliation 任务**
- **事实**：钱包/MoMo/ZaloPay 下单后订单只在 IPN 回调翻 `paid`；网关调用虽移出 DB 事务但仍无补偿/对账机制。
- **利用（半主动）**：触发支付后干扰/拦截回调通道，制造大量"已付款未发货"——越南客户钱已扣、平台不履约。可制造海量投诉 + 信用卡 chargeback，**搞垮 MoMo/ZaloPay 通道评级与越南市场口碑**。

> **🌐 跨境维度（本前提新增，黑客最该盯的结构弱点）**：代码在中国写、构建链/CI/崩溃上报/任何遥测很可能默认指向中国侧基础设施。若生产环境的日志、错误上报（如 Sentry/崩溃 SDK）或后台监控回连中国服务器，黑客只需攻陷**中国侧那一个监控端点**，即可批量获取越南生产库的 PII/凭证——单点穿透两国。且"中国开发团队直连越南生产库排障"本身在 PDPD 下就是未申报的跨境处理。建议：生产监控/日志必须落在越南或合规第三国，开发侧与生产严格网络隔离。

## 😤 视角二：最挑剔的越南用户（体验 / 可靠性 / 信任）

### 1. 🔴 支付卡死无自愈
钱包付完 IPN 没回来 → 订单永远 `pending_payment`，页面转圈；钱扣了货不来；App 无"我已付款/催单"入口，后台无对账兜底。越南用户直接卸载 + 应用商店差评。

### 2. 🔴「抢单」模式无 SLA、无兜底派单
商家点 ready 后订单进公共 `picked` 池等附近骑手抢（见 RiderController）。若片区骑手全忙/离线，订单**无限等待**，无超时改派/平台调度。用户看到"已出餐"却 40 分钟没人接——在摩托车外卖文化盛行的越南，这是致命体验缺陷。

### 3. 🟠 注销即失去全部历史 + 重注册清零
`destroyAccount` 软删 + 匿名化 + 吊销 token。用户注销后再也查不到过往订单/发票；同一手机重注册是全新账号。对要报销/售后/维权的越南用户是**数据黑洞**；且依 **PDPD** 用户有"访问/携带/删除"权，当前"删了就再也看不到自己数据"的体验违背数据主体权利精神。

### 4. 🟠 退款失败 fail-open 不透明
取消后若网关退款失败，订单标 `cancelled` + `refund_error`，前端只显示"已取消"。用户以为退了，月底对账发现**钱没退**——在越南《消费者保护法》下，这种"显示已取消但资金未返还"的不透明可被认定为侵害消费者知情权。

### 5. 🟠 数据信任危机：我的数据会不会跑去中国？
**本前提下的特有信任弱点**：尽管宣称"与中国无关系"，但代码/团队确实来自中国。最挑剔用户会问：我的地址、电话、GPS 是不是被中国团队看得到？若隐私政策（VI+ZH，见合规文档）未**用越南语明确说明数据处理者、是否跨境、存放在哪**，越南用户会因不信任而流失。PDPD 要求跨境传输须**明示同意**——隐私政策必须越南语 + 跨境条款清晰，否则既违规又丢用户。

> 附注：合并订单某商家缺货/拒单时的整体行为不清晰；骑手 GPS 偏差 >0.3km 时 `deliver` 直接 422 无提示。

## 💰 视角三：最抠门的老板（单位经济 / 烧钱 / 运维 + 合规成本）

### 1. 🔴【致命】PSP 手续费列已加但全代码零写入 → 单位经济全盲
- **位置**：`database/migrations/2026_08_01_120000_compliance_hardening.php:34` + `config/payment.php:68`；grep 全仓**无任何 `->update(['psp_fee'=>...])`**
- **事实**：`orders.psp_fee` 与 `psp_fee_bearer` 已建好，但没有任何代码路径写入。每笔 MoMo/ZaloPay/聚合单 PSP 抽 ~1.5–3.5%，平台既不记录也不入账。
- **影响**：0 佣金 + 平台补贴配送 + 平台出资新人券，再叠加一笔**完全没量化**的 PSP 成本 → 每单都是"未知金额的亏损"，老板连亏多少都看不到。

### 2. 🔴 注册无 OTP = 假账号 farm 平台补贴券，纯现金燃烧
（同黑客 #2）平台出资新人券被脚本批量薅，直接烧钱，且无法与真越南用户区分。

### 3. 🔴 0 佣金 + 平台全额补贴配送，没有任何收入线
平台收入 = 0；支出 = 骑手补贴 + 新人券 + PSP 费 + 服务器。代码把"纯烧钱"模型完整实现，无变现/抽成开关（连商户券都是商户出资）。**规模越大亏越多**。

### 4. 🟠 无水平扩展 + 队列与 web 同体 + 同步调 PSP
单容器单主机（`docker-compose.yml` 单服务）。`pay()` 网关调用仍请求内同步阻塞（虽移出 DB 事务）；无队列处理结算/通知/对账。规模上来一个慢 PSP 拖垮整个 worker 池；无自动扩缩容。宕机 = 全天订单流失 + 越南客诉爆发（越南社媒传播快，口碑修复贵）。

### 5. 🟠 **本前提新增：PDPD 合规成本 + 跨境开发结构的法律/运维代价**
- **数据本地化压力**：PDPD 对跨境传输设严格条件（同意 + 影响评估 + A05 报备）。若监管趋严要求数据留越，老板要么在越南本地托管（比中国/通用云贵、选择少），要么为每一类跨境处理做评估报备——**直接抬高合规与运维成本**。
- **中国开发团队访问生产 = 未申报跨境处理**：开发在国内排障时直连越南生产库/日志，在 PDPD 下可能构成违法跨境处理，面临罚款/责令整改。**必须付代价做"开发-生产网络隔离 + 脱敏镜像"**，否则是定时炸弹。
- **退款 fail-open 的人工对账 + chargeback 罚金**（同前）：每笔失败退款需财务人工追，量大是隐形人头成本；争议引发信用卡 chargeback（罚金 + 通道评级下降）。
- **叠加成本**：`RiderController::nearby()` 无分页无围栏 → 查询随订单数线性膨胀；Pusher 按连接计费；骑手实时位置写主表（写放大）。

## 跨视角共识（最该先修的 3 件 + 本前提新增隔离项）
1. **`nearby` 加地理围栏 + 分页 + 脱敏**（黑客 #1 / 老板 #5 同源）—— 堵 PII 拖库、降 DB 成本、满足 PDPD 数据最小化。
2. **注册强制 OTP + 设备/风控**（黑客 #2 / 用户信任 / 老板 #2）—— 堵最大现金出血点。
3. **PSP 费写入支付流 + 加 reconciliation 任务**（老板 #1 / 黑客 #5）—— 让单位经济可见、卡死订单自愈。
4. **🌐 本前提新增：生产-开发跨境隔离**：生产日志/监控/崩溃上报落地越南或合规第三国；中国开发侧禁止直连生产库，改走脱敏镜像 + 跳板审批；隐私政策用**越南语**写明数据处理者、存储地、是否跨境及同意机制（满足 PDPD 跨境条款 + 消除用户视角 #5 信任危机）。

> 说明：本报告为静态代码审查（红队视角），非渗透实测，亦非法律意见。越南 PDPD/SBV/消费者保护合规建议上线前聘越南当地律师 + DPO 复核。PIPL 因"无中国数据主体、无中国处理目的"明确不适用。
