# GIAONHANH 融资 BP 诚实叙事修正草案

> 目的：把 BP / Pitch 里容易被 DD（尽职调查）戳穿的夸大表述，改成**可验证、可辩护**的诚实叙事。
> 原则：**讲清楚"做到了什么、正在做什么、还没做什么"，比"已经领先"更经得起查。**
> 这份草案对应 Phase 0（融资前技术就绪）第 ④ 步。

---

## 1. 为什么必须修正

投资人在 DD 阶段一定会验证三件事：**代码真的跑过吗、App 真的上架了吗、数据真的在越南吗**。
当前仓库的真实状态是：业务正确性成熟（支付/安全/订单/结算/12 测试），但**从未在 prod 真跑过、无原生壳上架、CI 四 job 配好却未触发**。
任何"已上线 / 已分布式 / 已服务 X 万用户"的类表述，一旦被要求演示或查仓库，会直接摧毁信任。诚实叙事反而加分。

## 4. 融资问答诚实答案卡（DD 五题）

1. **跑过吗？** 后端全链路 smoke 测试（`tools/backend-smoke.mjs`）覆盖注册→下单→合并单→支付→结算→出款台账；CI（pest + backend-smoke）已配置，**首次绿证待 push 触发**。生产环境尚未 7×24 运行。
2. **亏多少 / 单位经济？** 当前 0 佣金 + 平台补贴骑手配送费 = 每单净成本；分账系统已就位，可随时切佣金 % 或增值服务变现。**具体 LTV/CAC 模型需在公测后基于真实数据填充**，BP 中标注为假设。
3. **App 上架了吗？** PWA 已可演示；原生应用构建中，尚未提交 Google Play / TestFlight。不宣称"已上架"。
4. **合规吗？** 已具备注册 OTP、PII 加密存储、隐私政策/服务条款/商户协议/跨境 runbook；越南支付需完成 PSP 生产签约与数据本地化部署。
5. **数据在越南吗？** 架构支持（数据库独立部署 + 内部网络隔离已做）；**多区域本地化与容灾为 Phase 2 规划**，当前为单区域部署。

## 5. 建议主动写进 BP 风险章的披露

- 单实例 / 单库部署，规模化前需做分片 + 只读副本 + Redis 集群（Phase 2）。
- 调度能力尚处早期，是履约体验与单位经济的关键风险。
- 营收模型尚未激活（0 佣金期），变现路径需在 A 轮前验证。
- 关键第三方依赖（MoMo / ZaloPay 签约、短信网关）存在商务与合规不确定性。
