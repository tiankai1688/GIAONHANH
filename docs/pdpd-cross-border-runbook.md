# PDPD 跨境处理合规 Runbook — GIAONHANH（越南上线 / 中国开发）

> **性质**：运维与法务行动清单（非代码）。需真人 / 越南本地合规律师落地。
> **场景**：软件在中国开发，最终在越南运营，数据主体为越南用户（C 消费者 / 商家 / 骑手）。
> **本文不是法律意见**；仅把《第 13/2023/NĐ-CP 号议定》（越南《个人数据保护令》，下称 PDPD）下与本产品相关的义务列成可执行的检查项。

---

## 1. 适用法域判定（关键前提）

| 维度 | 结论 |
|---|---|
| 中国《个人信息保护法》(PIPL) | **不适用**。无中国数据主体、无以中国为处理目的的控制者/处理者，开发行为本身不触发 PIPL 域外适用。 |
| 越南 PDPD (13/2023/NĐ-CP) | **适用**。数据主体位于越南，控制者/处理者在越南向越南用户提供商品或服务 → 域内适用，与"代码在哪里写"无关。 |
| 跨境维度 | "中国开发 + 越南运营" = **跨境处理**：越南境内收集的个人数据，由在越南运营的系统处理，其底层开发/运维支持链可能涉及境外（中国）主体 → 触发 PDPD 对**向境外提供个人数据**的要求。 |

**结论**：合规重心是 **PDPD**，不是 PIPL。下面的清单全部围绕 PDPD。

---

## 2. 控制者 / 处理者角色

- **控制者 (Data Controller)**：在越南注册运营 GIAONHANH 的法律实体（签约商户、向用户担责的一方）。须在当地有实体或法定代表。
- **处理者 (Data Processor)**：技术供应商（含软件开发方）。若开发/运维方位于中国，它属于"境外处理者"或"境外数据接收方"，须受数据处理协议 (DPA) 约束。
- **商户 / 骑手**：既是数据主体，也是（商户侧）部分数据的控制者。平台须在隐私政策中明确分层关系。

---

## 3. 上线前必须完成的清单（A05 报备 + 基础义务）

> 责任方：越南运营实体的合规负责人 + 外部越南律师。

- [ ] **建立个人信息保护部门（PDPD Unit）**：依 PDPD 设立专职/兼职数据保护负责人与部门，明确职责与上报链。
- [ ] **向 A05 报备（通知）**：向越南公安部 A05 局（Cục An ninh mạng và phòng, chống tội phạm công nghệ cao）书面**通知**该保护部门的设立及其联络方式，并按要求提交处理活动信息。此即俗称的 "A05 报备"。
- [ ] **跨境提供合法性基础**：对传输至境外（开发/运维方）的任何个人数据，取得数据主体**明示同意**，或确认落入 PDPD 允许的例外（如履行合同所必需）。同意须可撤回、可审计。
- [ ] **签署 DPA（数据处理协议）**：与境外开发/运维方签署，约定处理目的、范围、留存、删除、再转移禁止、安全与审计权。
- [ ] **隐私政策本地化并公示**：VI+ZH 双语（用户面向越南，主语言 VI），明确收集项、用途、保留期、跨境流向、数据主体权利与联系方式。已有 `docs/privacy-policy.md`，须补充**跨境章节**并上线可见入口。
- [ ] **数据主体权利通道**：访问 / 更正 / **删除（被遗忘权）** / 撤回同意。代码层已实现 `DELETE /account`（含历史订单 PII 匿名化），须配套人工受理入口与 SLA。
- [ ] **安全事件 72h 通报**：建立泄露发现→A05 通报（不超过 72 小时）的预案与演练记录。
- [ ] **留存最小化与删除**：明确各数据类型留存期，T+1 结算等保留商业记录但须剥离 PII（已实现匿名化），到期自动/人工删除。
- [ ] **同意与处理记录可审计**：所有同意、授权、跨境传输留痕，可供监管查验。

## 4. 代码层已就绪的支撑（无需重复开发）

- `DELETE /api/v1/account` 注销 + 历史订单 PII 匿名化（名称/电话/地址/GPS/备注），商业金额保留供审计 → 满足被遗忘权。
- 支付走持牌聚合/直连，平台不碰资金（避免二清），降低金融合规面。
- 刷新令牌 HttpOnly Cookie + API 源 CSP → 降低账户接管与数据外泄面。
